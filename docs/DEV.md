# PackageSurface development

This guide describes reproducible local validation for the repository. Consumer installation and the five-minute workflow are documented in the root and package READMEs.

## Prerequisites

- .NET SDK `8.0.425`, selected by `global.json`.
- PowerShell 7 or later.
- Network access only for the first controlled restore of public build dependencies; analysis itself is offline after restore.

## Validation sequence

```powershell
pwsh -NoProfile -File scripts/run-local-gate.ps1
```

The gate is self-contained. It first restores the shipping solution into a fresh run-owned package cache, then runs the controlled fixture restore, Release build, permanent corpus checks, hostile-input checks, no-code-execution and no-network proofs, package inspection, dependency audit, isolated tool smoke, and telemetry suppression checks. Phase 0 uses its own disposable fixture cache; it cannot delete or redirect the cache used by the shipping build and pack steps. The telemetry check verifies that the CLI makes one argument-free activation call and that [PRIVACY.md](../PRIVACY.md) states the product-specific data boundary; the shared client owns event fields, opt-out, identity, local state, delivery, and retention as documented in its [privacy policy](https://github.com/KeelMatrix/Telemetry/blob/main/PRIVACY.md). Record the exact command, duration, exit code, and result with the validation evidence for each completed candidate.

To run the release workflow source-guard regressions without the remaining release-contract cases, use:

```powershell
pwsh -NoLogo -NoProfile -File scripts/test-release-contract.ps1 -SourceGuardOnly
```

For a clean cache-isolation repeat, restore the solution into a fresh run-owned cache and then invoke the same gate; the gate performs its own shipping restore as an additional cache-invariant check:

```powershell
dotnet restore KeelMatrix.PackageSurface.sln --configfile NuGet.config --packages <fresh-run-cache> --no-cache --force
pwsh -NoLogo -NoProfile -File scripts/run-local-gate.ps1
```

On Linux/macOS, the gate derives `DOTNET_ROOT` from the `dotnet` executable when the variable is unset before invoking the installed tool apphost. This keeps the installed-tool smoke independent of whether the SDK was installed under a system path or a user-local SDK path; an existing `DOTNET_ROOT` is preserved.

## Packaging invariant

The packable CLI requires the repository-root `icon.png`. Packing fails with an actionable error when that file is absent; when it is present, the package must contain `icon.png` and nuspec metadata pointing to it. The local gate verifies both the package asset and metadata. The icon is a manually supplied repository asset and is not generated by the build.

## Release version and artifacts

For a tagged release, the version from `v<version>` is validated against the packable project's version and the finalized changelog before it becomes the release workflow's version output. The workflow passes that value into the local package gate and exact `.nupkg`/`.snupkg` validation before upload. The publish and GitHub Release jobs check the downloaded artifact set inline; they do not invoke tracked repository scripts. The release-contract tests enforce this layout and fail if a downstream artifact job starts invoking a tracked script.

If a future artifact job needs a tracked script, scripts/ReleaseWorkflowSourceGuard.ps1 is the source of truth for its pinned workspace-source contract. The guard requires an unconditional root checkout of github.repository at github.sha before the last preceding artifact download and verifies the source again at each guarded invocation. Action checkout paths accept only an omitted value or ., ./, and ./.; backslash paths, mixed separators, and subdirectories fail. Shell redirection, Git output options, common direct file mutations, and response/file sinks invalidate source state when they can write inside the workspace. Coverage includes curl short-option bundles and output, dump-header, stderr, trace, cookie-jar, alt-svc, HSTS, ETag-save, and write-out file destinations; wget document, log, cookie, and WARC outputs; and PowerShell Invoke-WebRequest/Invoke-RestMethod OutFile options, including aliases, module-qualified commands, and unambiguous parameter prefixes. Bash backslash and PowerShell backtick line continuations are analyzed as one command. Unsupported or dynamic write destinations fail closed unless proven outside by the immutable ${{ runner.temp }} expression with a suffix that stays within the temporary directory and no earlier recognized path redirect; mutable shell RUNNER_TEMP values never prove an external path. Explicit curl --config/-K inputs, nested shell or evaluator commands (including Bash/sh -c, PowerShell -Command/Invoke-Expression, encoded commands, and dynamic evaluators), and recognized symlink, junction, hard-link, or reparse-point creation fail closed. The command-token analysis resolves interpreter and script sources after supported assignments and wrapper chains. Code from stdin, pipelines, or here-documents fails closed. Bash and PowerShell dot/source, PowerShell -File, direct script calls, and equivalent loaders are accepted only for static paths under tracked scripts/; the complete workflow check verifies that each path is tracked and pinned. Unbounded nested process launchers such as xargs, parallel, and find -exec/-ok fail closed; find file-output actions such as -fprint and -fls also fail closed. Unsupported or dynamic loaders fail closed. After any unsupported evaluator, external script, or path-link step, later runner-temp paths are not treated as external, even after a pinned checkout. Unredirected read-only Git inspection preserves source state. A pinned shell git checkout or git switch --detach preserves valid source but cannot restore modified tracked bytes. Only an unconditional root checkout action at the workflow SHA, with clean omitted or explicitly true and without continue-on-error, restores invalid source. A conditional checkout to the same pinned repository and revision can preserve valid source but cannot restore invalid state. A checkout or switch to another ref, repository, or directory breaks the proof. The downloaded artifact set is checked before OIDC authentication or release creation; missing, invalid, or mismatched versions and any extra or missing artifact stop the workflow.

The source guard records each artifact output location. Workspace outputs that overlap tracked files invalidate the proof until a clean root checkout restores them. A qualified executable or interpreter input under an artifact output remains untrusted regardless of its name. PATH overrides and persistent PATH additions fail closed in artifact-consuming jobs. Artifact files used only as data remain allowed when they do not overlap tracked source; safe system wrappers remain allowed when their lookup stays on the trusted runner PATH. A clean root checkout cannot clear persistent PATH changes or external artifact outputs.

GNU `cp --link` and `cp --symbolic-link`, including supported unique long-option prefixes and clustered `-l` / `-s` forms, count as path-link operations that invalidate later runner-temp path proofs. Artifact-consuming workflows fail closed when `BASH_ENV` or `BASHOPTS` is set at workflow, job, or step scope, or when a run step up to and including a guarded invocation references `GITHUB_ENV`, because Bash startup files and alias expansion can run before a guarded command. Artifact-consuming jobs that declare a job-level `container` also fail closed: `container.env`, Docker-backed `container.options` (`--env`, `-e`, or `--env-file`), and image-defined `ENV` values cannot be proven free of `BASH_ENV` or `BASHOPTS`. Job-level YAML merges fail closed because they can inherit container or startup settings; service containers remain allowed because they do not set the job shell environment. The guard checks block mapping keys in plain, single-quoted, double-quoted, and explicit-key forms. It scans flow-style job mappings for a direct `container` key and rejects unsupported flow job mappings. A direct `container` entry is rejected regardless of whether its value is scalar, block, flow, or an alias; unsupported mapping keys and job-level merges fail closed.

Artifact and executable paths use the runner's POSIX, Windows drive/root-relative, or UNC path flavor, including dot segments, before overlap checks. This covers absolute outputs inside the workspace and relative/absolute invocation cross-products while preserving external absolute outputs used only as data. If the runner and guard checkout use different path flavors, literal absolute paths fail closed because their workspace relationship cannot be proven. Workflow and job `env` maps and step `env` maps are checked in block and flow YAML, with quoted or plain keys in any case. Multiline flow maps account for braces inside escaped quoted values and comments; unsupported nested maps and multiline quoted scalars fail closed. PATH changes through `GITHUB_ENV`, `GITHUB_PATH`, toolkit `addPath`, or unsupported actions fail closed across steps before and after downloads and between guarded invocations; the supported `actions/setup-dotnet` control remains allowed. On Windows, bare `cmd` names are treated as current-directory lookups when the working directory overlaps an artifact output, including executable suffixes from `PATHEXT`; a present `NoDefaultCurrentDirectoryInExePath` entry removes that bare-name check, but path-qualified commands remain checked. In-run working-directory changes and cmd launch forms that can invoke nested commands fail closed while artifact outputs are in scope.

The local gate derives its expected package version from the evaluated packable project unless a validated release version is supplied with `-ExpectedVersion`.

The guard also rejects wrapped stdin interpreter forms, including `env --`, `env -S`, and GNU `timeout` or `gtimeout` (including qualified executable paths), with the timeout `--` option terminator before its duration; indentation-preserving block-scalar script loaders; and downloaded runner-temp or artifact-output executables invoked by absolute or relative path, after changing directory, or through PATH. Code-loading forms are classified from command tokens after supported assignments and wrappers; dynamic and untracked inputs fail closed, while a static input under tracked `scripts/` remains subject to the pinned-source checks. Nested code-execution launchers such as `xargs`, `parallel`, Bash `coproc`, PowerShell jobs/parallel scriptblocks, and `find -exec`/`-ok` fail closed; find file-output actions such as `-fprint` and `-fls` also fail closed. The guard does not trust artifact executables because their names match known system wrappers or interpreters. Bash tracked-script paths must use forward slashes; PowerShell script paths may use backslashes. Unsafe execution or link creation keeps later runner-temp paths untrusted across shell checkout or switch. Ordinary runner-temp output remains allowed while that proof is intact.

The guard parses `exec -a` and GNU `time -o`/`--output` wrapper options, and recognizes GNU `timeout` and `gtimeout` kill-after and signal values in separate, attached, and `=` forms. Timeout parsing consumes the duration after `--` and fails closed when a required option value, duration, or command is missing. The guard rejects `env -S` values containing environment expansion, rejects variable-expanded executable names (including Bash variables that name downloaded runner-temp helpers), and fails closed when wrapper parsing reaches its depth bound. GNU time output destinations are checked as file sinks; immutable `runner.temp` expression paths with safe suffixes remain allowed while no path redirect is active.

The source guard carries each supported wrapper directory into relative executable and script resolution. It tracks `env -C`/`--chdir` and `sudo -D`/`--chdir` across nested wrappers and normalized paths. Sudo short-option bundles are parsed flag by flag, required values are consumed before the command is located, and login mode is rejected whenever `i` appears as a flag. Unknown or ambiguous sudo options, missing values, chroot mode, and login mode fail closed. A relative code input must still resolve to the same pinned tracked path from the effective wrapper directory as from the workflow step; when a directory cannot be proven, the guard rejects relative code inputs.

## Project roles

- `src/KeelMatrix.PackageSurface.Cli` is the only shipping packable project and produces the `KeelMatrix.PackageSurface` .NET tool.
- `src/KeelMatrix.PackageSurface.Core` contains the non-executing graph classifier and is not packable on its own.
- `src/KeelMatrix.PackageSurface.Probe` preserves the Phase 0 executable probe.
- `src/KeelMatrix.PackageSurface.Cli` is the shipping packable tool. The controlled projects under
  `fixtures/packages` are deliberately packable test-package fixtures used to build the local feed; fixture
  consumers, tests, probes, and tools are explicitly non-packable. `scripts/test-packability.ps1` audits this
  allowlist so a new project cannot silently become another NuGet artifact.

The classifier consumes existing restore evidence. It does not restore, evaluate MSBuild, load dependency assemblies, execute package code, or query a package feed. The canonical [restore and baseline safety reference](restore-and-baseline-safety.md) owns the detailed restore schema, XML context, path identity, and baseline output contract.

## Restore framework compatibility evidence

The focused tests cover restore formats 3 and 4, including SDK-produced assets from SDK 8.0.425, 9.0.121, and 10.0.401. They exercise framework aliases, RID-qualified targets, SDK-shaped metadata, graph closure, malformed identities, baseline output path aliases, filesystem identity, and supported MSBuild import contexts. Keep test evidence aligned with the canonical reference when changing these contracts.

To record the native assets format emitted by a locally installed SDK for a zero-dependency `net8.0` project, run:

```powershell
pwsh -NoLogo -NoProfile -File scripts/test-assets-format.ps1 -SdkVersion 10.0.401
```

The pinned SDK remains `8.0.425`; this evidence script does not change repository SDK selection or commit generated assets.
